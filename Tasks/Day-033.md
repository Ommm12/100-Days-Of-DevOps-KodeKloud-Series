# Understanding the Problem

Initial Situation:

Local Repository:

```text
Max's Changes
```

Remote Repository:

```text
Sarah's Changes
```

When Max attempted:

```bash
git push origin master
```

Git rejected the push because remote history had changed.

---

# Why Push Failed

Git protects repository history.

Example:

Remote:

```text
A → B → C
```

Local:

```text
A → B → D
```

Git cannot decide automatically which version should win.

Result:

```text
Push Rejected
```

# Important Concept – Merge Conflict

## What is a Merge Conflict?

Occurs when:

Two developers modify the same section of a file.

Example:

Sarah:

```text
Mouse
```

Max:

```text
Mooose
```

Git cannot determine which version is correct.

Requires manual resolution.

---

# Conflict Markers

Git inserts:

```text
<<<<<<< HEAD
Your Version
=======
Remote Version
>>>>>>> branch-name
```

These markers must be removed.

---

# Interview Questions

## 1. What causes a Git merge conflict?

When multiple developers modify the same part of a file and Git cannot automatically merge the changes.

---

## 2. How do you resolve a merge conflict?

- Open conflicted file
- Remove conflict markers
- Keep correct content
- Stage file
- Commit changes

---

## 3. Why was the push rejected?

Because remote repository contained commits that were not available locally.

---

## 4. What command updates your local repository with remote changes?

```bash
git pull origin master
```

---

## 5. How can you identify merge conflicts?

Using:

```bash
git status
```

Git will display conflicted files.
