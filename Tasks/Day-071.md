# Day 71 – Configure Jenkins Job for Package Installation

---

# Task Overview

The Nautilus DevOps team wanted to automate package installation across infrastructure using Jenkins. Instead of manually logging into servers and installing packages, they decided to create a parameterized Jenkins job that could install any package specified by the user.

The objective was to:

* Create a Jenkins job named `install-packages`
* Add a string parameter named `PACKAGE`
* Install the package specified by the parameter
* Execute installation on the Storage Server
* Verify package installation
* Build the job successfully

# What is a Parameterized Job?

A parameterized job accepts user input during build time.

Example:

```text
PACKAGE=vim-enhanced
```

or

```text
PACKAGE=git
```

or

```text
PACKAGE=wget
```

Same Jenkins job can install different packages.

# Script Breakdown

## Install Package

```bash
sudo yum install -y $PACKAGE
```

Meaning:

| Part     | Purpose               |
| -------- | --------------------- |
| sudo     | Execute as root       |
| yum      | Package manager       |
| install  | Install package       |
| -y       | Auto approve          |
| $PACKAGE | User supplied package |

# Common Mistakes

## Mistake 1 – Wrong Parameter Name

Wrong:

```text
package
```

Required:

```text
PACKAGE
```

---

## Mistake 2 – Forgetting Parameter Expansion

Wrong:

```bash
yum install PACKAGE
```

Correct:

```bash
yum install $PACKAGE
```

---

## Mistake 3 – Missing Sudo

Wrong:

```bash
yum install -y $PACKAGE
```

May fail due to permissions.

Correct:

```bash
sudo yum install -y $PACKAGE
```

---

## Mistake 4 – Not Building Job

Task requires:

```text
Build at least once
```

Use:

```text
PACKAGE=vim-enhanced
```

# Interview Questions

## What is a Parameterized Jenkins Job?

A Jenkins job that accepts input values during build execution.

## Why use String Parameters?

To make jobs reusable without modifying job configuration.

## How do you reference a Jenkins parameter in Shell?

```bash

```
