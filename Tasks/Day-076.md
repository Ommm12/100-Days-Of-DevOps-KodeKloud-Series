# Day 76 – Jenkins Project Security

---

# Task Overview

The xFusionCorp Industries DevOps team needed to provide controlled access to an existing Jenkins project for newly joined developers.

Instead of granting full Jenkins access, the team decided to use Project-Based Security to assign only the required permissions on a specific Jenkins job.

The objective was to:

* Configure project-level security for an existing Jenkins job
* Grant specific permissions to user `sam`
* Grant specific permissions to user `rohan`
* Use inheritance from parent ACL
* Ensure no other job configurations are modified

# Understanding the Problem

Without Project Security:

```text
Users
   │
   ▼
Full Access
```

Security Risk:

* Unwanted changes
* Job deletion
* Unauthorized modifications

---

With Project Security:

```text
Users
   │
   ▼
Specific Permissions
   │
   ▼
Specific Job
```

Better security and access control.

---

# What is Project-Based Security?

Project-Based Security allows permissions to be assigned directly to individual Jenkins jobs.

Example:

```text
User A → Read Only

User B → Build + Read

User C → Full Control
```

# Common Mistakes

## Mistake 1 – Wrong Inheritance

Wrong:

```text
Do not inherit
```

Correct:

```text
Inherit permissions from parent ACL
```

---

## Mistake 2 – Extra Permissions

Giving:

```text
Delete
Workspace
Administer
```

will fail validation.
