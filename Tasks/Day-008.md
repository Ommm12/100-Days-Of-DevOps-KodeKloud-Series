#  Day 08 – Install and Configure Ansible

##  Task Overview
The Nautilus DevOps team decided to begin testing infrastructure automation and configuration management using **Ansible**.

To prepare the environment, the Jump Host needed to be configured as an **Ansible Controller** by installing a specific Ansible version globally so that all users on the system could execute Ansible commands.

###  Objective

- Install **Ansible 4.10.0** on the Jump Host  
- Use **pip3** for installation only  
- Ensure Ansible commands are globally accessible for all users  

---

#  Why This Task Matters

Modern DevOps environments rely heavily on automation tools to manage infrastructure efficiently.

Ansible is one of the most widely used automation tools for:
- Configuration management
- Server provisioning
- Application deployment
- Infrastructure automation

Unlike many tools, Ansible is:
- Agentless
- Simple to configure
- SSH-based

This makes it extremely popular in production environments.

#  Step-by-Step Implementation

---

# 🔹 Step 1: Connect to the Jump Host

```bash
ssh thor@jumphost.stratos.xfusioncorp.com
```

###  Explanation
Use SSH to securely connect to the Jump Host, which will act as the Ansible controller node.

---

# 🔹 Step 2: Verify Python and pip3 Availability

```bash
python3 --version
pip3 --version
```

###  Explanation
Ansible installation through `pip3` requires:
- Python 3
- pip3 package manager

---

# 🔹 Step 3: Install Ansible 4.10.0 Using pip3

```bash
sudo pip3 install ansible==4.10.0
```

###  Explanation
This installs:
- Ansible 4.10.0
- Required Python dependencies

Using `sudo` ensures the installation is available system-wide for all users.

---

# 🔹 Step 4: Verify Installed Ansible Version

```bash
ansible --version
```

###  Explanation
Expected output should include:

```bash
ansible [core 2.11.x]
```

and:

```bash
ansible 4.10.0
```

### Important Note
Ansible package version and Ansible Core version are different:

| Component | Version |
|-----------|---------|
| Ansible Package | 4.10.0 |
| ansible-core | 2.11.x |

This is expected behavior.

---

# 🔹 Step 5: Verify Global Accessibility

Switch to another user or verify directly:

```bash
which ansible
```

Expected output:

```bash
/usr/local/bin/ansible
```

###  Explanation
This confirms:
- Ansible is installed globally
- All users can execute Ansible commands
