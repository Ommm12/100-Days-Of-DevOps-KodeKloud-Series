# 🚀 Day 01 – Linux User Setup with Non-Interactive Shell

## 📌 Task Overview
As part of the infrastructure hardening process at **xFusionCorp Industries**, the system administration team needed to create a dedicated user account for an automated backup agent.

Since the account was intended only for background service operations and not for human interaction, the requirement was to configure the user with a **non-interactive shell**.

### 🎯 Objective
Create a user named `mark` with a non-interactive shell on **App Server 3**.

---

# 🧠 Why This Task Matters

In production environments, not every user account should have terminal access.

Service accounts used by:
- backup tools
- monitoring agents
- automation scripts
- application runtimes

should be restricted from interactive login to reduce security risks.

This follows the **Principle of Least Privilege** — giving users only the permissions they actually need.

---

# 🛠️ Step-by-Step Implementation

## 🔹 Step 1: Connect to the Application Server

```bash
ssh banner@stapp03.stratos.xfusioncorp.com
```

### 📖 Explanation
Use SSH to securely access the target Linux server where the user needs to be created.

---

## 🔹 Step 2: Create the User with a Non-Interactive Shell

```bash
sudo useradd -m -s /sbin/nologin mark
```

### 📖 Explanation
The `useradd` command creates a new Linux user account.

### Command Breakdown

| Option | Purpose |
|--------|---------|
| `-m` | Creates a home directory |
| `-s /sbin/nologin` | Assigns a non-interactive shell |
| `mark` | Username |

The `/sbin/nologin` shell prevents the user from accessing the terminal interactively.

---

## 🔹 Step 3: Verify User Creation

```bash
cat /etc/passwd | grep mark
```

### 📖 Explanation
This checks whether the user was successfully created and confirms the assigned shell.

Expected output:

```bash
mark:x:1003:1003::/home/mark:/sbin/nologin
```

This confirms:
- User exists
- Home directory is created
- Non-interactive shell is assigned

---

## 🔹 Step 4: Validate Login Restriction

```bash
sudo su - mark
```

### 📖 Explanation
Attempting to switch to the user should fail with a message similar to:

```bash
This account is currently not available.
```

This verifies that interactive login has been successfully disabled.

---

# 🔍 Additional Verification Commands

## Check User Details
```bash
id mark
```

## List Users with Non-Interactive Shells
```bash
grep nologin /etc/passwd
```

## Remove User (if required)
```bash
sudo userdel -r mark
```

# 🔐 Security Best Practices

- Use non-interactive shells for service and automation accounts
- Avoid giving unnecessary shell access to applications
- Never run services directly as `root`
- Apply least-privilege access wherever possible
- Separate human users from system/service users
