#  Day 09 – MariaDB Service Troubleshooting

##  Task Overview
The production support team at **xFusionCorp Industries** reported a critical issue affecting one of the applications running in the Stratos Datacenter.

The application was unable to connect to its backend database, and after investigation, the root cause was identified as:

> The MariaDB service was down on the database server.

###  Objective

- Investigate the database service issue  
- Identify the root cause  
- Restore MariaDB service functionality  
- Ensure the application can reconnect successfully  

---

#  Why This Task Matters

Databases are the backbone of most modern applications.

If a database service becomes unavailable:
- Applications stop functioning
- APIs fail
- User requests break
- Production outages occur

Troubleshooting database availability is one of the most important real-world responsibilities of a DevOps or Production Support Engineer.

---

#  Step-by-Step Implementation

---

# 🔹 Step 1: Connect to the Database Server

```bash
ssh peter@stdb01.stratos.xfusioncorp.com
```

###  Explanation
Use SSH to securely access the database server where the MariaDB service issue was reported.

---

# 🔹 Step 2: Check MariaDB Service Status

```bash
sudo systemctl status mariadb
```

###  Explanation
This command checks:
- Whether the service is running
- Service health status
- Error messages or failure reasons

Observed issue:

```bash
Active: failed
```

This confirmed that the database service was down.

---

# 🔹 Step 3: Start the MariaDB Service

```bash
sudo systemctl start mariadb
```

###  Explanation
Attempts to start the MariaDB database server service.

---

# 🔹 Step 4: Enable MariaDB at Boot

```bash
sudo systemctl enable mariadb
```

###  Explanation
Ensures the database service starts automatically after server reboot.

---

# 🔹 Step 5: Verify Service Recovery

```bash
sudo systemctl status mariadb
```

###  Explanation
Expected output:

```bash
active (running)
```

This confirms:
- MariaDB is operational
- Database services are restored

---

# 🔹 Step 6: Verify Listening Database Port

```bash
sudo ss -tulnp | grep 3306
```

###  Explanation
MariaDB typically listens on:

```bash
3306
```

This verifies:
- Database is actively listening for connections
- Service is reachable internally

---

# 🔹 Step 7: Validate Database Connectivity

```bash
mysql -u root -p
```

###  Explanation
Tests whether the database server accepts connections successfully.

---

#  Additional Verification Commands

## Check Service Logs
```bash
sudo journalctl -xeu mariadb
```

## Verify Running Process
```bash
ps -ef | grep mysql
```

## Verify Port Availability
```bash
sudo netstat -tulnp | grep 3306
```
