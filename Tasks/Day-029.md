# Day 29 – Manage Git Pull Requests

---

# Task Overview

Modern software development relies heavily on collaboration between developers. Instead of pushing code directly to the main branch, developers create feature branches and submit Pull Requests (PRs) for review.

This task focused on understanding the Pull Request workflow and how code changes move from a feature branch into the master branch through a review process.

---

# Objective

Understand and implement the Pull Request workflow:

1. Create a feature branch
2. Make code changes
3. Commit changes
4. Push branch to remote repository
5. Create Pull Request
6. Review and approve changes
7. Merge Pull Request into master

---

# What is a Pull Request?

A Pull Request (PR) is a request to merge changes from one branch into another.

Example:

```text
feature-login
      │
      ▼
Pull Request
      │
      ▼
master
```

A Pull Request allows:

- Code review
- Collaboration
- Quality checks
- Automated testing
- Approval workflows

---

# Why Pull Requests Are Important

Without Pull Requests:

```text
Developer
    │
    ▼
Direct Push to Master
```

Risk:

- Bugs reach production
- No review process
- No quality checks

---

With Pull Requests:

```text
Developer
    │
    ▼
Feature Branch
    │
    ▼
Pull Request
    │
    ▼
Review + Testing
    │
    ▼
Merge
```

Benefits:

- Better code quality
- Team collaboration
- Reduced production issues

# Step-by-Step Workflow

## Step 1 – Clone Repository

```bash
git clone <repository-url>
```

### Explanation

Downloads repository from remote server.

---

## Step 2 – Create Feature Branch

```bash
git checkout -b feature-login
```

### Explanation

Creates a new branch for development work.

---

## Step 3 – Make Changes

Example:

```bash
echo "Login Feature Added" >> app.txt
```

---

## Step 4 – Check Status

```bash
git status
```

### Explanation

Shows modified files waiting to be committed.

---

## Step 5 – Stage Changes

```bash
git add .
```

### Explanation

Adds modified files to the staging area.

---

## Step 6 – Commit Changes

```bash
git commit -m "Added login functionality"
```

### Explanation

Creates a commit containing the changes.

---

## Step 7 – Push Feature Branch

```bash
git push origin feature-login
```

### Explanation

Uploads branch to remote repository.

---

## Step 8 – Create Pull Request

On GitHub, GitLab, Bitbucket, or Gitea:

1. Open repository
2. Navigate to Pull Requests
3. Click New Pull Request
4. Select:

```text
Source Branch: feature-login
Target Branch: master
```

5. Add title and description
6. Submit Pull Request

# Merge Strategies

## 1. Merge Commit

```text
Master
    │
    ├── Commit A
    │
Feature
    │
    ├── Commit B
    │
    ▼
Merge Commit
```

Preserves full history.

---

## 2. Squash Merge

Combines all feature commits into one commit.

Before:

```text
A
B
C
D
```

After:

```text
Single Commit
```

---

## 3. Rebase Merge

Creates linear history.

Cleaner but rewrites commit history.

# Common Mistakes

## Mistake 1 – Direct Push to Master

Wrong:

```bash
git push origin master
```

Without review.

---

## Mistake 2 – Large Pull Requests

Huge PRs are difficult to review.

Best practice:

Small and focused PRs.

---

## Mistake 3 – Skipping Reviews

Every production change should be reviewed.

---

## Mistake 4 – Merging Without Testing

Always verify:

- Build passes
- Tests pass
- Security checks pass

# Interview Questions

## 1. What is a Pull Request?

A Pull Request is a request to merge changes from one branch into another after review and validation.

---

## 2. Why are Pull Requests important?

They enable:

- Collaboration
- Code review
- Quality assurance
- Safe deployments

---

## 3. What is the difference between Merge and Pull Request?

A merge combines code, while a Pull Request is the workflow used to review and approve changes before merging.

---

## 4. What happens before a Pull Request is merged?

Typically:

- Review
- Testing
- CI/CD validation
- Approval

---

## 5. What are common merge strategies?

- Merge Commit
- Squash Merge
- Rebase Merge
