# Day 53 – Troubleshoot and Fix VolumeMounts Issue in Kubernetes

---

# Task Overview

The Nautilus DevOps team encountered a production issue with an Nginx + PHP-FPM application running inside a Kubernetes Pod. The website became inaccessible because the shared storage configuration between containers was incorrect.

The application consisted of:

* Nginx Container
* PHP-FPM Container
* Shared Volume
* ConfigMap-based Nginx Configuration

The goal was to investigate the issue, identify the misconfiguration, fix the Pod, copy the application file, and restore the website.

This task was one of the first real Kubernetes troubleshooting challenges in the 100 Days of DevOps journey.

# Understanding the Architecture

Application Design:

```text id="5"
                Shared Volume
                     │
      ┌──────────────┴──────────────┐
      │                             │
      ▼                             ▼

 Nginx Container              PHP-FPM Container

```

Both containers must use the same shared volume path.

# The Root Cause

During investigation:

```bash id="6"
kubectl get pod nginx-phpfpm -o yaml
```

we discovered:

```yaml id="7"
php-fpm-container:

mountPath: /usr/share/nginx/html
```

while Nginx was configured as:

```yaml id="8"
root /var/www/html;
```

inside ConfigMap:

```yaml id="9"
nginx-config
```

Result:

```text id="10"
PHP writes files here:
└── /usr/share/nginx/html

Nginx reads files here:
└── /var/www/html
```

Different paths → Website failure.

# Troubleshooting Process

## Step 1 – Verify Pod Status

```bash id="13"
kubectl get pods
```

### Explanation

Confirms Pod is running before debugging.

---

# Step 2 – Inspect Pod Configuration

```bash id="14"
kubectl get pod nginx-phpfpm -o yaml
```

### Explanation

Exports complete Pod configuration.

---

# Step 3 – Inspect ConfigMap

```bash id="15"
kubectl describe configmap nginx-config
```

### Important Finding

```nginx id="16"
root /var/www/html;
```

Nginx expected files under:

```text id="17"
/var/www/html
```

---

# Step 4 – Export Pod YAML

```bash id="18"
kubectl get pod nginx-phpfpm -o yaml > /tmp/nginx.yaml
```

### Explanation

Creates editable Pod configuration backup.

---

# Step 5 – Edit Pod Configuration

```bash id="19"
vi /tmp/nginx.yaml
```

Find:

```yaml id="20"
mountPath: /usr/share/nginx/html
```

Replace with:

```yaml id="21"
mountPath: /var/www/html
```

---

# Why This Fix Works

Before:

```text id="22"
PHP-FPM
   │
   ▼
/usr/share/nginx/html
```

After:

```text id="23"
PHP-FPM
   │
   ▼
/var/www/html
```

Now both containers share the same directory.

# Common Mistakes

## Mistake 1 – Editing Running Pod Directly

Wrong:

```bash id="36"
kubectl edit pod nginx-phpfpm
```

Volume mounts cannot be modified on running Pods.

Correct:

```bash id="37"
Export → Modify → Delete → Recreate
```

---

## Mistake 2 – Copying File to Wrong Path

Wrong:

```bash id="38"
/usr/share/nginx/html
```

Correct:

```bash id="39"
/var/www/html
```

---

## Mistake 3 – Using Wrong Container Name

Wrong:

```bash id="40"
-c nginx-container
```

without checking actual container name.

Always verify:

```bash id="41"
kubectl get pod nginx-phpfpm -o yaml
```

---

## Mistake 4 – Forgetting Shared Volume Concept

Both containers must mount:

```text id="42"
Same Volume
Same Path
```

for proper application functionality.

# Interview Questions

## 1. What is a VolumeMount in Kubernetes?

A mechanism that allows containers to access storage volumes.

---

## 2. What is a Shared Volume?

A volume mounted into multiple containers inside the same Pod.

---

## 3. Why was the website failing?

Because Nginx and PHP-FPM were using different mount paths.

---

## 4. Why couldn't the Pod be edited directly?

Certain Pod specifications such as volumes and mounts are immutable after creation.

---

## 5. How do you copy files into a container?

```bash id="43"
kubectl cp
```

Example:

```bash id="44"
kubectl cp file pod:path
```
