# Day 62 – Manage Secrets in Kubernetes

---

# Task Overview

The Nautilus DevOps team needed to deploy applications on a Kubernetes cluster that require sensitive information such as passwords, API keys, license numbers, and certificates.

Storing sensitive information directly inside Pod manifests or container images is not secure. To address this, Kubernetes Secrets were used to securely store and consume confidential data within the cluster.

The objective was to:

* Create a Kubernetes Secret named `media`
* Load secret data from an existing file `/opt/media.txt`
* Create a Pod named `secret-datacenter`
* Mount the Secret inside the container
* Verify that the secret data is accessible from within the Pod

# Step 7 – Add Pod Configuration

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: secret-datacenter

spec:
  containers:
  - name: secret-container-datacenter
    image: ubuntu:latest

    command:
    - sleep
    - infinity

    volumeMounts:
    - name: media-volume
      mountPath: /opt/cluster

  volumes:
  - name: media-volume
    secret:
      secretName: media
```

# Common Mistakes

## Mistake 1 – Wrong Secret Name

Wrong:

```yaml
secretName: license
```

Actual:

```yaml
secretName: media
```

Result:

```text
Pod Creation Failure
```

---

## Mistake 2 – Missing Volume Mount

Without:

```yaml
volumeMounts:
```

Secret cannot be accessed.

---

## Mistake 3 – Wrong Mount Path

Wrong:

```yaml
mountPath: /data
```

Expected:

```yaml
mountPath: /opt/cluster
```

---

## Mistake 4 – Pod Exits Immediately

Wrong:

```yaml
command:
- bash
```

Result:

```text
Container Terminates
```

Use:

```yaml
sleep infinity
```
