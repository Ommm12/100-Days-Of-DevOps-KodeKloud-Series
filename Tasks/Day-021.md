# Day 21 – Setup Git Repository on Storage Server

---

#  Task Overview

The Nautilus development team requested the DevOps team to set up a centralized Git repository for a new application development project on the Storage Server in Stratos Datacenter.

### Requirements:
- Install the `git` package using `yum`
- Create a bare Git repository named:

```bash
/opt/media.git
```

---

#  Infrastructure Details

| Server | Hostname | User |
|---|---|---|
| Storage Server | ststor01.stratos.xfusioncorp.com | natasha |

---

#  Step-by-Step Implementation

## Step 1 – Connect to the Storage Server

```bash
ssh natasha@ststor01
```

###  Explanation
The `ssh` (Secure Shell) command is used to securely connect to a remote Linux server.

- `natasha` → username
- `ststor01` → storage server hostname

This allows us to access the server where the repository needs to be created.

---

# Step 2 – Switch to Root User

```bash
sudo su -
```

###  Explanation
Administrative privileges are required because:

- Installing packages requires root access
- Creating repositories under `/opt` requires elevated permissions

### Command Breakdown

| Command | Meaning |
|---|---|
| `sudo` | Execute command with elevated privileges |
| `su` | Switch user |
| `-` | Load root user's environment variables |

---

# Step 3 – Install Git Package

```bash
yum install git -y
```

###  Explanation
This command installs Git from the configured YUM repositories.

### Command Breakdown

| Part | Meaning |
|---|---|
| `yum` | Package manager for RHEL/CentOS |
| `install` | Install a package |
| `git` | Git version control package |
| `-y` | Automatically answer "yes" to prompts |

---

# Step 4 – Verify Git Installation

```bash
git --version
```

### Expected Output

```bash
git version 2.x.x
```

###  Explanation
This confirms Git has been installed successfully and is available in the system path.

---

# Step 5 – Create Bare Git Repository

```bash
git init --bare /opt/media.git
```

###  Explanation
This command creates a **bare Git repository**.

A bare repository:
- Does NOT contain working files
- Is mainly used as a **central/shared repository**
- Allows developers to push and pull code

### Command Breakdown

| Part | Meaning |
|---|---|
| `git init` | Initialize a new Git repository |
| `--bare` | Create repository without working directory |
| `/opt/media.git` | Repository location and name |

---

# Step 6 – Verify Repository Creation

```bash
ls -ld /opt/media.git
```

### Expected Output

```bash
drwxr-xr-x 7 root root 119 media.git
```

###  Explanation
The `ls -ld` command verifies:
- Repository exists
- Permissions are correct
- Directory ownership details

---

#  Important Concept – Bare Repository

## What is a Bare Repository?

A bare repository contains only:
- Git objects
- Branch references
- Commit history

It does NOT contain:
- Checked-out files
- Working directory

---

#  Why Bare Repositories are Used

Bare repositories are commonly used for:

✅ Central Git servers  
✅ Team collaboration  
✅ Remote repositories  
✅ CI/CD integration  

Examples:
- GitHub repositories
- GitLab repositories
- Bitbucket repositories

---

#  Real DevOps Insight

In real production environments:

- Developers clone repositories from central Git servers
- CI/CD tools pull code from these repositories
- Bare repositories act as the single source of truth

Example workflow:

```text
Developer → Push Code → Central Bare Repo → CI/CD Pipeline → Deployment
```

#  Interview Questions You Can Answer Now

### 1. What is a bare Git repository?
A bare repository is a Git repository without a working directory, mainly used as a central/shared repository for collaboration.

---

### 2. Why do we use `--bare` in Git?
The `--bare` option creates a repository intended for remote sharing and collaboration without checked-out source files.

---

### 3. Difference between normal repo and bare repo?

| Normal Repo | Bare Repo |
|---|---|
| Contains working files | No working files |
| Used for development | Used for sharing |
| Developers edit code | Developers push/pull code |
