# Day 52 – Roll Back a Kubernetes Deployment to the Previous Version

---

# Task Overview

Earlier in the day, the Nautilus DevOps team deployed a new version of an application running in Kubernetes. Shortly after deployment, a customer reported a bug affecting the application.

To quickly restore service stability, the team decided to revert the Deployment back to the previously working version using Kubernetes Rollback functionality.

This task introduced another critical production concept: **Deployment Rollbacks**.

The objective was to:

* Identify Deployment revision history
* Roll back to the previous Deployment version
* Verify rollback success
* Ensure all Pods return to a healthy state

# What is a Rollback?

A Rollback restores a Deployment to a previously working revision.

Instead of manually redeploying:

```text id="87m9on"
Find Old YAML
      │
      ▼
Modify Files
      │
      ▼
Redeploy
```

Kubernetes provides:

```bash id="8m3qms"
kubectl rollout undo
```

---

# Why Rollbacks Matter?

Benefits:

* Faster recovery
* Reduced downtime
* Safer deployments
* Simplified incident response
* Production-grade release management

---

# Kubernetes Deployment Revisions

Each Deployment update creates a new revision.

Example:

```text id="w9d6dk"
Revision 1 → nginx:latest
Revision 2 → nginx:1.18
```

If Revision 2 fails:

```text id="uoh4rw"
Rollback
     │
     ▼
Revision 1
```

---

# Deployment Revision Architecture

```text id="r2ww3j"
Deployment
      │
      ▼
Revision 1
      │
      ▼
Revision 2
      │
      ▼
Revision 3
```

Kubernetes stores revision history automatically.

# Common Mistakes

## Mistake 1 – Using Wrong Deployment Name

Wrong:

```bash id="j7hytq"
kubectl rollout undo deployment/nginx
```

Correct:

```bash id="p9sm9u"
kubectl rollout undo deployment/nginx-deployment
```

---

## Mistake 2 – Not Checking Revision History

Always inspect:

```bash id="3rlrdu"
kubectl rollout history deployment/nginx-deployment
```

before rollback.

---

## Mistake 3 – Forgetting to Verify Rollback

Always run:

```bash id="1fcrp1"
kubectl rollout status deployment/nginx-deployment
```

---

## Mistake 4 – Assuming Rollback Changes YAML

Rollback updates Deployment state in Kubernetes.

Original YAML files are not automatically modified.
