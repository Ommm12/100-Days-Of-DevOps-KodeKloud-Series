# Day 12 – Apache Service Troubleshooting and Port Conflict Resolution

## Task Overview
The monitoring system reported that Apache service was unreachable on port 8087 on one of the application servers.

The objective was to:
- Identify the issue
- Restore Apache service
- Ensure external accessibility from the Jump Host
- Resolve any service or port conflicts

---

# Objective

- Restore Apache functionality
- Configure Apache on port 8087
- Resolve service conflicts
- Verify connectivity from Jump Host

---

# Why This Task Matters

Production outages often occur because of:
- Port conflicts
- Misconfigured services
- Failed daemons
- Resource contention

This task simulates a real-world production troubleshooting scenario.

---

# Step-by-Step Implementation

## Step 1: Connect to App Server

```bash
ssh tony@stapp01.stratos.xfusioncorp.com
```

---

## Step 2: Check Apache Service Status

```bash
sudo systemctl status httpd
```

Observed:

```bash
failed
```

---

## Step 3: Check Port Usage

```bash
sudo netstat -tulnp | grep 8087
```

Root cause identified:
- Sendmail was occupying the required port

---

## Step 4: Stop Conflicting Service

```bash
sudo systemctl stop sendmail
sudo systemctl disable sendmail
```

---

## Step 5: Configure Apache Port

```bash
sudo vi /etc/httpd/conf/httpd.conf
```

Set:

```bash
Listen 8087
```

---

## Step 6: Start Apache

```bash
sudo systemctl start httpd
sudo systemctl enable httpd
```

---

## Step 7: Verify Port Availability

```bash
sudo ss -tulnp | grep 8087
```

---

## Step 8: Validate Accessibility

```bash
curl http://stapp01:8087
```

From Jump Host:

```bash
curl http://stapp01:8087
```
