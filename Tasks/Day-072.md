# Task Overview

A new DevOps Engineer joined the team and was assigned a simple Jenkins task to understand the fundamentals of parameterized builds.

Parameterized jobs allow users to provide input values at build time, making Jenkins jobs dynamic and reusable.

The objective was to:

* Create a parameterized Jenkins job
* Add String and Choice parameters
* Pass values during build execution
* Display parameter values in build logs
* Execute the job successfully

# What are Parameterized Builds?

Parameterized Builds allow users to provide values when starting a build.

Example:

```text
Stage = Build
env = Development
```

or

```text
Stage = Test
env = Staging
```

or

```text
Stage = Deploy
env = Production
```

The same Jenkins job can be reused for multiple environments.

# Common Mistakes

## Mistake 1 – Wrong Parameter Name

Wrong:

```text
stage
```

Required:

```text
Stage
```

Parameter names are case-sensitive.

---

## Mistake 2 – Missing Choice Values

Required:

```text
Development
Staging
Production
```

Missing one causes task validation failure.

---

## Mistake 3 – Forgetting $ Symbol

Wrong:

```bash
echo Stage
```

Correct:

```bash
echo $Stage
```

---

## Mistake 4 – Building with Wrong Environment

Task requires:

```text
Staging
```

Build at least once using:

```text
env = Staging
```

# Interview Questions

## What is a Parameterized Build?

A Jenkins build that accepts user input during execution.

---

## What is a String Parameter?

A parameter that accepts text input.

Example:

```text
Build
Test
Deploy
```

---

## What is a Choice Parameter?

A parameter that provides predefined selectable values.

Example:

```text
Development
Staging
Production
```

---

## How do you access Jenkins parameters in Shell?

Using:

```bash
$PARAMETER_NAME
```

Example:

```bash
$Stage
$env
```

# Real DevOps Insight

Parameterized jobs are widely used in production CI/CD pipelines.

Example:

```text
Deploy Application
      │
      ▼
Environment:
Development

Staging

Production
```

Instead of creating three jobs, one parameterized job handles all environments.
