# Day 39 – Create a Docker Image from a Running Container

---

# Task Overview

The Nautilus DevOps team needed to preserve the current state of a running container by creating a reusable Docker image from it.

Instead of building an image using a Dockerfile, the requirement was to:

- Use an existing container
- Capture all changes inside the container
- Create a new Docker image from that container
- Verify the newly created image

This process is performed using:

```bash
docker commit
```

Create a Docker image from an existing container and verify the image creation.

# Understanding the Problem

Current Situation:

```text
Docker Image
      │
      ▼
Running Container
      │
      ▼
Modified Files
Installed Packages
Configuration Changes
```

Goal:

```text
Running Container
        │
        ▼
docker commit
        │
        ▼
New Docker Image
```

The new image should contain all changes currently present inside the container.

---

# What is Docker Commit?

Docker Commit creates a new image from a container's current state.

Think of it like:

```text
Taking a Snapshot
```

of the container.

---

# Real World Example

Suppose inside a container you:

```bash
apt install nginx
```

```bash
mkdir /backup
```

```bash
echo "DevOps" > info.txt
```

Normally these changes exist only in the container.

Using:

```bash
docker commit
```

all changes become part of a reusable image.

---

# Step 3 – Identify Target Container

Example:

```bash
ubuntu_latest
```

or

```bash
d91ab1234abc
```

This container will be converted into an image.

---

# Step 4 – Create Docker Image

Syntax:

```bash
docker commit <container> <image-name>:<tag>
```

Example:

```bash
docker commit ubuntu_latest ubuntu:nautilus
```

### Explanation

Creates a new image named:

```bash
ubuntu:nautilus
```

from the container:

```bash
ubuntu_latest
```

---

# Command Breakdown

| Part | Meaning |
|----------|----------|
| docker | Docker CLI |


# Why Use Docker Commit?

Useful for:

- Quick backups
- Saving container state
- Troubleshooting
- Creating custom images

---

# Docker Commit vs Dockerfile

## Docker Commit

```bash
docker commit
```

Pros:

- Fast
- Simple

Cons:

- Not reproducible
- Hard to track

---

## Dockerfile

```dockerfile
FROM ubuntu
RUN apt install nginx -y
```

Pros:

- Reproducible
- Version controlled

Cons:

- Requires writing configuration

---

# Real DevOps Insight

In production:

```text
Dockerfile
```

is preferred.

However:

```bash
docker commit
```

is useful for:

- Emergency backups
- Debugging environments
- Capturing temporary container states

# Common Mistakes

## Mistake 1 – Using Image Instead of Container

Wrong:

```bash
docker commit ubuntu:latest newimage
```

Must use:

```bash
Container Name
```

or

```bash
Container ID
```

---

## Mistake 2 – Container Not Running

Verify:

```bash
docker ps
```

before commit.

---

## Mistake 3 – Wrong Image Tag Syntax

Wrong:

```bash
docker commit ubuntu_latest nautilus
```

Preferred:

```bash
docker commit ubuntu_latest ubuntu:nautilus
```

---

## Mistake 4 – Forgetting Verification

Always verify:

```bash
docker images
```

after commit.

# Interview Questions

## 1. What does `docker commit` do?

Creates a new image from a container's current state.

---

## 2. Does docker commit preserve installed packages?

Yes.

Everything inside the container becomes part of the image.

---

## 3. What is the difference between a Docker Image and a Container?

| Image | Container |
|---------|---------|
| Blueprint | Running Instance |
| Static | Dynamic |
| Read-only | Writable |

---

## 4. Why is Dockerfile preferred over Docker Commit?

Dockerfiles are reproducible, version controlled, and easier to maintain.

```bash
docker images
```
