# Day 98 – Launch EC2 in Private VPC Subnet Using Terraform

---

# Task Overview

The Nautilus DevOps team continued expanding their AWS infrastructure by creating a completely private network environment. Instead of launching an EC2 instance in a public subnet, they needed to build a secure architecture where the instance could communicate only within the VPC.

This task involved creating:

* A custom VPC
* A private subnet
* A security group restricted to internal VPC traffic
* An EC2 instance inside the private subnet
* Variables and outputs using Terraform best practices

The objective was to:

* Create a VPC named `datacenter-priv-vpc`
* Create a private subnet named `datacenter-priv-subnet`
* Disable auto-assign public IPs
* Create an EC2 instance named `datacenter-priv-ec2`
* Restrict access to only VPC internal traffic
* Use Terraform variables and outputs
* Follow Infrastructure as Code principles

# What is a Private Subnet?

A private subnet is a subnet where:

```text
No Public IP

No Direct Internet Access
```

Resources inside can communicate only:

```text
Within VPC
```

or through controlled networking paths.

# Why Variables?

Instead of:

```hcl
cidr_block = "10.0.0.0/16"
```

Use:

```hcl
cidr_block = var.KKE_VPC_CIDR
```

Benefits:

* Reusable
* Flexible
* Cleaner Code

# Step 2 – Create main.tf

```bash
vi main.tf
```

Add:

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "5.91.0"
    }
  }
}

provider "aws" {
  region                      = "us-east-1"
  skip_credentials_validation = true
  skip_requesting_account_id  = true
  s3_use_path_style           = true

  endpoints {
    ec2 = "http://aws:4566"
  }
}

resource "aws_vpc" "datacenter_vpc" {

  cidr_block = var.KKE_VPC_CIDR

  tags = {
    Name = "datacenter-priv-vpc"
  }
}

resource "aws_subnet" "datacenter_subnet" {

  vpc_id = aws_vpc.datacenter_vpc.id

  cidr_block = var.KKE_SUBNET_CIDR

  map_public_ip_on_launch = false

  tags = {
    Name = "datacenter-priv-subnet"
  }
}

resource "aws_security_group" "private_sg" {

  name   = "private-sg"

  vpc_id = aws_vpc.datacenter_vpc.id

  ingress {

    from_port = 0

    to_port   = 65535

    protocol  = "tcp"

    cidr_blocks = [var.KKE_VPC_CIDR]
  }

  egress {

    from_port = 0

    to_port   = 0

    protocol  = "-1"

    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "private_ec2" {

  ami = "ami-0c101f26f147fa7fd"

  instance_type = "t2.micro"

  subnet_id = aws_subnet.datacenter_subnet.id

  vpc_security_group_ids = [
    aws_security_group.private_sg.id
  ]

  tags = {
    Name = "datacenter-priv-ec2"
  }
}
```

Save file.

# Common Mistakes

## Mistake 1 – Enabling Public IPs

Wrong:

```hcl
map_public_ip_on_launch = true
```

Correct:

```hcl
map_public_ip_on_launch = false
```

---

## Mistake 2 – Using 0.0.0.0/0 in Security Group

Wrong:

```hcl
cidr_blocks = ["0.0.0.0/0"]
```

Task requires:

```hcl
cidr_blocks = [var.KKE_VPC_CIDR]
```

---

## Mistake 3 – Hardcoding CIDRs

Wrong:

```hcl
cidr_block = "10.0.0.0/16"
```

Use:

```hcl
var.KKE_VPC_CIDR
```

---

## Mistake 4 – Forgetting Outputs

Validation checks:

```text
KKE_vpc_name

KKE_subnet_name

KKE_ec2_private
```

# Interview Questions

## 1. What is a Private Subnet?

A subnet where resources do not receive public IP addresses and cannot be directly accessed from the Internet.

---

## 2. Why disable public IP assignment?

To keep workloads private and secure.

---

## 3. What is the purpose of a Security Group?

Acts as a virtual firewall controlling inbound and outbound traffic.

To make configurations reusable and flexible.
