# Day 57 – Print Environment Variables in Kubernetes

---

# Task Overview

The Nautilus DevOps team was preparing a sample application that generates greeting messages using environment variables. Instead of hardcoding values inside the container, the application needed to read values from Kubernetes environment variables.

This task introduced one of the most important Kubernetes concepts: **Environment Variables**.

Environment variables allow applications to receive configuration dynamically without modifying application code.

The objective was to:

* Create a Pod named `print-envars-greeting`
* Use the `bash` image
* Create three environment variables
* Print a greeting message using those variables
* Set restart policy to `Never`
* Verify output using Pod logs

# What are Environment Variables?

Environment Variables are key-value pairs provided to a container at runtime.

Example:

```text id="11"
GREETING=Welcome to
```

Application reads:

```bash id="12"
$GREETING
```

Result:

```text id="13"
Welcome to
```

---

# Why Use Environment Variables?

Benefits:

* Dynamic configuration
* Better security
* Easier deployments
* Environment-specific settings
* Cloud-native application design

# Step 3 – Add Pod Configuration

```yaml id="17"
apiVersion: v1
kind: Pod

metadata:
  name: print-envars-greeting

spec:
  restartPolicy: Never

  containers:
  - name: print-env-container
    image: bash

    command:
    - /bin/sh
    - -c
    - echo "$(GREETING) $(COMPANY) $(GROUP)"

    env:
    - name: GREETING
      value: "Welcome to"

    - name: COMPANY
      value: "xFusionCorp"

    - name: GROUP
      value: "Industries"
```
