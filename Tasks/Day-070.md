# Day 70 – Configure Jenkins User Access

---

# Task Overview

The Nautilus DevOps team integrated Jenkins into their CI/CD environment and needed to provide controlled access to development team members.

Instead of granting full administrator privileges, they implemented Role-Based Access Control using Jenkins' Project-based Matrix Authorization Strategy.

The objective was to:

* Create a new Jenkins user
* Configure Project-based Matrix Authorization
* Grant Overall Read access to the new user
* Remove Anonymous user permissions
* Grant Job Read access only
* Preserve Admin access for the administrator

# What is Matrix Authorization?

Matrix Authorization allows assigning permissions per user.

Example:

```text id="u5s66y"
User A → Admin

User B → Read

User C → Build
```

Each user receives only required permissions.

# Interview Questions

## What is Matrix Authorization Strategy?

A Jenkins security model that allows permissions to be assigned individually to users.

---

## Why remove Anonymous access?

To prevent unauthorized users from viewing Jenkins resources.

---

## What is the Principle of Least Privilege?

Users should receive only the permissions required to perform their tasks.

---

## Difference between Authentication and Authorization?

Authentication:

```text id="n09r4n"
Who are you?
```

Authorization:

```text id="48j66n"
What can you do?
```
