# Day 82 – Create Ansible Inventory for App Server Testing

---

# Task Overview

The Nautilus DevOps team wanted to test Ansible playbooks on App Server 3. Before any playbook execution, Ansible requires an inventory file that defines which servers it should manage and how it should connect to them.

The objective was to:

* Create an Ansible inventory file
* Add App Server 3 as a managed node
* Configure authentication variables
* Ensure playbooks can run without additional command-line arguments
* Validate Ansible connectivity

---

# Infrastructure Details

| Server       | Hostname  | User   |
| ------------ | --------- | ------ |
| Jump Host    | jump-host | thor   |
| App Server 3 | stapp03   | banner |

Inventory File:


Target Host:

# What is an Ansible Inventory?

An Inventory is a file that tells Ansible:

* Which servers to manage
* How to connect
* Which credentials to use

It acts as the source of truth for managed infrastructure.

---

# Why DevOps Teams Use Inventory Files

Benefits:

* Centralized server management
* Simplified automation
* Scalable infrastructure control
* Environment organization

Example:

```text
Inventory
    │
    ├── Web Servers
    ├── App Servers
    └── Database Servers
```


Insert:

---

# Inventory Breakdown

```ini
stapp03 ansible_user=banner ansible_ssh_pass=BigGr33n
```

| Part             | Meaning               |
| ---------------- | --------------------- |
| stapp03          | Target Host           |
| ansible_user     | SSH User              |
| banner           | Remote Login User     |
| ansible_ssh_pass | SSH Password Variable |
| BigGr33n         | Remote Password       |

# Step 5 – Verify Inventory

Expected Output:

```ini
stapp03 ansible_user=banner ansible_ssh_pass=BigGr33n
```

# Step 6 – Test Connectivity

