#  Day 06 – Create and Configure a Cron Job

##  Task Overview
The Nautilus system administration team wanted to automate repetitive operational tasks across all application servers in the Stratos Datacenter.

Before deploying production automation scripts, the team decided to test scheduled task execution using a sample cron job.

###  Objective

- Install the `cronie` package on all application servers  
- Start and enable the `crond` service  
- Configure a cron job for the `root` user that runs every 5 minutes  

Cron job:

```bash
*/5 * * * * echo hello > /tmp/cron_text
```

---

#  Why This Task Matters

In production environments, many operational tasks are automated using scheduled jobs.

Common cron-based automation includes:
- Backups
- Log rotation
- Monitoring checks
- Cleanup scripts
- Health checks
- Scheduled deployments

Cron is one of the most important Linux automation utilities used by system administrators and DevOps engineers.

#  Step-by-Step Implementation

---

# 🔹 Step 1: Connect to the Application Server

Example for App Server 1:

```bash
ssh tony@stapp01.stratos.xfusioncorp.com
```

###  Explanation
Use SSH to securely access the target application server where the cron service needs to be configured.

Repeat the same process for:
- `stapp01`
- `stapp02`
- `stapp03`

---

# 🔹 Step 2: Install Cronie Package

```bash
sudo yum install -y cronie
```

###  Explanation
The `cronie` package provides:
- Cron daemon (`crond`)
- Scheduled task execution functionality

Without this package, cron jobs cannot run on the system.

---

# 🔹 Step 3: Start Cron Service

```bash
sudo systemctl start crond
```

###  Explanation
Starts the cron daemon responsible for executing scheduled tasks automatically.

---

# 🔹 Step 4: Enable Cron Service at Boot

```bash
sudo systemctl enable crond
```

###  Explanation
Ensures the cron service starts automatically after system reboot.

---

# 🔹 Step 5: Verify Cron Service Status

```bash
sudo systemctl status crond
```

###  Explanation
Verify the service status is:

```bash
active (running)
```

This confirms the scheduler service is operational.

---

# 🔹 Step 6: Configure Root User Cron Job

Open root crontab:

```bash
sudo crontab -e
```

Add the following line:

```bash
*/5 * * * * echo hello > /tmp/cron_text
```

Save and exit.

---

#  Cron Expression Breakdown

| Field | Meaning |
|--------|---------|
| `*/5` | Every 5 minutes |
| `*` | Every hour |
| `*` | Every day |
| `*` | Every month |
| `*` | Every weekday |

### Command Action

```bash
echo hello > /tmp/cron_text
```

Creates or overwrites the file:

```bash
/tmp/cron_text
```

with the content:

```bash
hello
```

every 5 minutes.

---

# 🔹 Step 7: Verify Cron Job Configuration

```bash
sudo crontab -l
```

###  Explanation
Displays all scheduled cron jobs configured for the root user.

Expected output:

```bash
*/5 * * * * echo hello > /tmp/cron_text
```

## Check Existing Cron Jobs



## Remove Root Cron Jobs
```bash
sudo crontab -r
```

#  Security Best Practices

- Avoid running unnecessary cron jobs as `root`
- Use dedicated service accounts where possible
- Monitor cron logs regularly
- Validate scripts before scheduling them
- Keep cron jobs documented and version-controlled
