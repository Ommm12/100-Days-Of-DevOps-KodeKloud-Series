# Day 79 – Jenkins Deployment Job

---

# Task Overview

The Nautilus Development Team wanted to automate application deployment whenever developers pushed new code to the Git repository.

Instead of manually copying files after each update, Jenkins was configured to automatically detect repository changes, pull the latest code, and deploy it to App Server 1.

This task introduced real-world Continuous Deployment concepts where a code push automatically triggers deployment.

The objective was to:

* Create a Jenkins Freestyle Job named `nautilus-app-deployment`
* Configure automatic builds from Gitea repository changes
* Deploy the latest application code to `/var/www/html`
* Ensure ownership permissions are correct
* Update application content and push changes to Git
* Verify deployment through the Load Balancer URL

# Common Issues We Debugged

## Issue 1 – Running On Jenkins Controller

Wrong:

```text
Build runs on Jenkins Server
```

Result:

```text
/var/www/html not found
```

Fix:

```text
Restrict build to stapp01
```

---

## Issue 2 – SSH From Agent To Same Server

Wrong:

```bash
ssh sarah@stapp01
```

inside build step.

Result:

```text
Host key verification failed
Permission denied
```

Fix:

```text
Run commands directly
```

because build already executes on App Server 1.

---

## Issue 3 – Deploying Only index.html

Wrong:

```bash
cp index.html /var/www/html/
```

Validation may fail.

Correct:

```bash
cp -r * /var/www/html/
```

---

## Issue 4 – Permission Problems

Wrong:

```text
root owns /var/www/html
```

Fix:

```bash
sudo chown -R sarah:sarah /var/www/html
```

# Interview Questions

## What is Continuous Deployment?

A process where application changes are automatically deployed after code is pushed.

---

## Why run jobs on an agent?

To execute deployment directly on target infrastructure.

---

## Difference Between Poll SCM and Webhook?

| Poll SCM           | Webhook              |
| ------------------ | -------------------- |
| Jenkins checks Git | Git notifies Jenkins |
| Less efficient     | More efficient       |

## Why clean deployment directory before copying?

To avoid serving outdated files.
