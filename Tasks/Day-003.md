# 🚀 Day 03 – Secure Root SSH Access

## 📌 Task Overview
Following internal security audits, the security team at **xFusionCorp Industries** identified a major security concern:

> Direct SSH login for the `root` user was enabled on all application servers.

To strengthen server security and reduce unauthorized privileged access risks, the team decided to disable direct root SSH login across the infrastructure.

### 🎯 Objective
Disable direct SSH login for the `root` user on all application servers in the Stratos Datacenter.

---

# 🧠 Why This Task Matters

The `root` user has unrestricted administrative access to the Linux system.

Allowing direct SSH access to `root` increases the risk of:
- Brute-force attacks
- Unauthorized access
- Privilege abuse
- Credential compromise

In production environments, administrators should:
- Login using normal users
- Then elevate privileges using `sudo`

This improves:
- Auditability
- Accountability
- Security compliance

---

# 🛠️ Step-by-Step Implementation

---

# 🔹 Step 1: Connect to the Application Server

Example for App Server 1:

```bash
ssh tony@stapp01.stratos.xfusioncorp.com
```

### 📖 Explanation
Use SSH to securely connect to the server using a non-root administrative user.

---

# 🔹 Step 2: Open SSH Configuration File

```bash
sudo vi /etc/ssh/sshd_config
```

### 📖 Explanation
The `sshd_config` file controls the behavior and security settings of the SSH service.

---

# 🔹 Step 3: Disable Root SSH Login

Find the following line:

```bash
PermitRootLogin yes
```

Change it to:

```bash
PermitRootLogin no
```

### 📖 Explanation
This setting disables direct remote login for the `root` account via SSH.

Users must now:
- Login using standard accounts
- Use `sudo` for administrative tasks

---

# 🔹 Step 4: Save Configuration Changes

Inside `vi` editor:

```bash
Esc
:wq
Enter
```

### 📖 Explanation
- `Esc` → Exit insert mode
- `:wq` → Save and quit

---

# 🔹 Step 5: Restart SSH Service

```bash
sudo systemctl restart sshd
```

### 📖 Explanation
Restarting the SSH daemon applies the updated security configuration.

---

# 🔹 Step 6: Verify SSH Service Status

```bash
sudo systemctl status sshd
```

### 📖 Explanation
Ensure the SSH service is:
```bash
active (running)
```

This confirms the configuration change was applied successfully.

---

# 🔹 Step 7: Repeat on All App Servers

Perform the same steps on:
- `stapp01`
- `stapp02`
- `stapp03`

---

# 🔍 Additional Verification Commands

## Check Root Login Setting
```bash
grep PermitRootLogin /etc/ssh/sshd_config
```

## Check SSH Service Status
```bash
sudo systemctl status sshd
```

## Verify Listening SSH Port
```bash
sudo ss -tulnp | grep ssh
```

---

# 🔐 Security Best Practices

- Never allow direct root SSH access in production
- Use `sudo` instead of logging in as root
- Implement least-privilege access
- Monitor SSH authentication logs regularly
- Use SSH keys instead of passwords wherever possible
