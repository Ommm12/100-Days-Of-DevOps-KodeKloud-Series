# Day 56 – Deploy Nginx Web Server on Kubernetes Cluster

---

# Task Overview

The Nautilus development team completed a static website and wanted to deploy it on Kubernetes with high availability and scalability.

To achieve this, the DevOps team decided to use a **Deployment** with multiple replicas and expose the application using a **NodePort Service**.

This task introduced one of the most important Kubernetes production concepts:

* Deployments for scalability
* Services for networking
* NodePorts for external access

The objective was to:

* Create a Deployment named `nginx-deployment`
* Use image `nginx:latest`
* Configure container name `nginx-container`
* Run 3 replicas
* Create a NodePort Service named `nginx-service`
* Expose application on NodePort `30011`

# What is a Deployment?

A Deployment manages Pods automatically.

Features:

* Self-healing
* Scaling
* Rolling updates
* Rollbacks
* High availability

---

# What is a Service?

A Service provides a stable network endpoint for Pods.

Without Service:

```text id="7"
Pod IP Changes
```

Applications break.

With Service:

```text id="8"
Stable Endpoint
```

Applications remain reachable.

---

# What is NodePort?

Example:

```text id="9"

   ▼

   │
   ▼
```

# Step 3 – Add Deployment Configuration

```yaml id="13"
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
      - name: nginx-container
        image: nginx:latest

        ports:
        - containerPort: 80
```

