# Day 77 – Jenkins Deploy Pipeline

---

# Task Overview

The xFusionCorp Industries development team created a static website and wanted to automate deployment using a Jenkins Pipeline.

Instead of manually copying files after every change, Jenkins was configured to deploy the application directly to App Server 1.

The objective was to:

* Create a Jenkins SSH Agent for App Server 1
* Create a Pipeline job named `datacenter-webapp-job`
* Deploy website content from the `web_app` repository
* Publish content directly under `/var/www/html`
* Ensure the application loads from the LB URL root path
* Successfully complete deployment using a single pipeline stage named `Deploy`

# Step 6 – Configure Pipeline

Under Pipeline:

```text
Pipeline Script
```

Paste:

```groovy
pipeline {
    agent {
        label 'stapp01'
    }

    stages {
        stage('Deploy') {
            steps {
                sh '''
                set -eux

                test -f /var/www/html/web_app/index.html

                rm -f /var/www/html/index.html

                cp /var/www/html/web_app/index.html /var/www/html/
                '''
            }
        }
    }
}
```

# Interview Questions

## What is a Jenkins Pipeline?

A Pipeline is a Jenkins job defined as code that automates build, test, and deployment workflows.

---

## Why use Jenkins Agents?

To execute jobs on remote infrastructure instead of the Jenkins controller.

---

## Why deploy to /var/www/html?

Because Apache serves files from the document root.

---

## Difference Between Freestyle and Pipeline Jobs?

| Freestyle         | Pipeline           |
| ----------------- | ------------------ |
| UI Driven         | Code Driven        |
| Limited           | Flexible           |
| Harder to Version | Version Controlled |
