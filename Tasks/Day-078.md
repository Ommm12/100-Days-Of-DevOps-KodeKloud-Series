# Day 78 – Jenkins Conditional Pipeline

---

# Task Overview

The xFusionCorp Industries development team wanted a Jenkins Pipeline capable of deploying different branches of the same application based on user input.

Instead of creating separate jobs for each branch, a single parameterized pipeline was created that conditionally deploys either the `master` or `feature` branch.

This task was particularly important because validation checked not only the Jenkins build status but also whether the correct content was served by the Load Balancer.

The objective was to:

* Add App Server 1 as a Jenkins Agent
* Create a Pipeline Job named `datacenter-webapp-job`
* Add a String Parameter named `BRANCH`
* Conditionally deploy `master` or `feature`
* Deploy content directly under `/var/www/html`
* Ensure LB serves the correct file from the root URL

# Step 7 – Configure Pipeline Script

Use:

```groovy
pipeline {
    agent {
        label 'stapp01'
    }

    parameters {
        string(
            name: 'BRANCH',
            defaultValue: 'master'
        )
    }

    stages {
        stage('Deploy') {
            steps {
                sh '''
                set -eux

                cd /var/www/html

                if [ ! -d web_app ]; then
                    git clone https://gitea-url/sarah/web_app.git
                fi

                cd web_app

                git fetch --all

                if [ "$BRANCH" = "master" ]; then
                    git checkout master
                    git pull origin master
                elif [ "$BRANCH" = "feature" ]; then
                    git checkout feature
                    git pull origin feature
                else
                    echo "Invalid branch"
                    exit 1
                fi

                rm -f /var/www/html/index.html
                rm -f /var/www/html/feature.html

                cp *.html /var/www/html/ || true

                ls -l /var/www/html
                '''
            }
        }
    }
}
```

Production deployment pipelines often use:


A single parameterized pipeline can deploy to multiple environments and branches, reducing maintenance overhead.
