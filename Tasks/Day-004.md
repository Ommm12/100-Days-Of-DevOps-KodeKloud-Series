#  Day 04 – Script Execution Permissions

##  Task Overview
The system administration team at **xFusionCorp Industries** developed a backup automation script named:

```bash
xfusioncorp.sh
```

Although the script had already been distributed to the application server, it was missing the required execution permissions.

To ensure all users on the server could execute the script successfully, proper Linux file permissions needed to be configured.

###  Objective
Grant executable permissions to:

```bash
/tmp/xfusioncorp.sh
```

on **App Server 1**, ensuring all users are able to execute the script.

---

#  Why This Task Matters

In Linux systems, scripts and binaries require proper execution permissions before users can run them.

Without executable permissions:
- Scripts cannot be executed
- Automation workflows fail
- Backup and deployment jobs may break

Managing file permissions correctly is a fundamental Linux administration skill and a critical part of production system operations.

---

#  Step-by-Step Implementation

---

# 🔹 Step 1: Connect to the Application Server

```bash
ssh tony@stapp01.stratos.xfusioncorp.com
```

###  Explanation
Use SSH to securely connect to the target server where the script is located.

---

# 🔹 Step 2: Verify Script Existence

```bash
ls -l /tmp/xfusioncorp.sh
```

###  Explanation
This command checks:
- Whether the script exists
- Current file permissions
- Ownership details

Example output before permission change:

```bash
-rw-r--r-- 1 root root 120 Feb 10 10:30 /tmp/xfusioncorp.sh
```

Notice:
- No `x` (execute) permission is present.

---

# 🔹 Step 3: Grant Execute Permission to All Users

```bash
sudo chmod a+x /tmp/xfusioncorp.sh
```

###  Explanation
The `chmod` command modifies file permissions.

### Command Breakdown

| Option | Meaning |
|--------|---------|
| `a` | All users (owner, group, others) |
| `+x` | Add execute permission |

This allows:
- Owner
- Group
- Other users

to execute the script.

---

# 🔹 Step 4: Verify Updated Permissions

```bash
ls -l /tmp/xfusioncorp.sh
```

###  Explanation
Expected output:

```bash
-rwxr-xr-x 1 root root 120 Feb 10 10:30 /tmp/xfusioncorp.sh
```

The presence of:
```bash
x
```

confirms executable permissions were applied successfully.

---

# 🔹 Step 5: Execute the Script

```bash
/tmp/xfusioncorp.sh
```

###  Explanation
This validates that:
- The script is executable
- Permissions are working correctly

---

#  Security Best Practices

- Grant execute permissions only when necessary
- Avoid giving unnecessary write permissions to all users
- Restrict sensitive scripts to authorized users only
- Use least-privilege principles in production environments
- Regularly audit executable files on servers
