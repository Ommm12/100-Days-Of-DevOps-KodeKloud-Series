# Day 23 – Fork a Git Repository

---

# Task Overview

The Nautilus development team required a separate copy of an existing repository for independent development and testing purposes. The task involved creating a forked version of the repository while preserving the original source repository.

### Requirements

- Fork an existing Git repository
- Maintain an independent copy for development
- Preserve commit history and repository structure

# Infrastructure Details

| Server | Hostname | User |
|---|---|---|
| Storage Server | ststor01.stratos.xfusioncorp.com | natasha |

# Step-by-Step Implementation

## Step 1 – Connect to the Storage Server

```bash
ssh natasha@ststor01
```

### Explanation

The `ssh` command establishes a secure connection to the remote Storage Server where repository operations will be performed.

---

# Step 2 – Navigate to Working Directory

```bash
cd /usr/src/kodekloudrepos
```

### Explanation

This directory stores cloned and managed repositories used by the development and DevOps teams.

---

# Step 3 – Clone the Original Repository

```bash
git clone /opt/cluster.git
```

### Explanation

The `git clone` command creates a local copy of the original repository.

### Command Breakdown

| Part | Meaning |
|---|---|
| `git clone` | Clone repository |
| `/opt/cluster.git` | Source repository path |

---

# Step 4 – Create a Separate Forked Repository

```bash
cp -r cluster cluster-fork
```

### Explanation

The `cp -r` command creates a recursive copy of the repository directory.

### Command Breakdown

| Part | Meaning |
|---|---|
| `cp` | Copy command |
| `-r` | Recursive copy |
| `cluster` | Original repository |
| `cluster-fork` | Forked repository |

---

# Step 5 – Navigate to Forked Repository

```bash
cd cluster-fork
```

### Explanation

Moves into the newly created forked repository directory.

---

# Step 6 – Verify Git Repository Status

```bash
git status
```

### Expected Output

```bash
On branch master
nothing to commit, working tree clean
```

### Explanation

Confirms that:
- The repository is valid
- Working tree is clean
- Git tracking is functioning correctly

---

# Step 7 – Verify Remote Repository

```bash
git remote -v
```

### Expected Output

```bash
origin  /opt/cluster.git (fetch)
origin  /opt/cluster.git (push)
```

### Explanation

Displays configured remote repositories associated with the forked repository.

---

# Important Concept – Forking vs Cloning

## What is Forking?

Forking creates an independent copy of a repository that can be modified without affecting the original repository.

---

# Difference Between Clone and Fork

| Clone | Fork |
|---|---|
| Local copy of repository | Independent repository copy |
| Connected to original repo | Separate development environment |
| Used for working locally | Used for isolated development |

---

# Real DevOps Insight

Forking is heavily used in:

- Open-source contributions
- Feature development
- Team collaboration
- Experimental development
- Independent testing environments

Typical workflow:

```text
Original Repository → Fork → Development → Testing → Merge/Pull Request
```

# Interview Questions You Can Answer Now

### 1. What is the difference between fork and clone?

A clone creates a local copy of a repository, while a fork creates an independent repository copy for separate development.

---

### 2. Why do developers fork repositories?

Developers fork repositories to:
- work independently
- test features safely
- contribute to open-source projects
- avoid affecting the original repository

---

### 3. What is the purpose of `git remote -v`?

It displays configured remote repository URLs for fetch and push operations.
