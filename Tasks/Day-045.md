# Day 45 – Troubleshoot and Fix a Broken Dockerfile

---

# Task Overview

The Nautilus DevOps team was tasked with building a custom Apache HTTP Server image using an existing Dockerfile. However, the image build process was failing due to configuration and file path issues within the Dockerfile.

The objective was not to redesign the Dockerfile but to investigate the errors, identify the root cause, and make only the necessary fixes while preserving the original application data and configuration.

This task simulated a real-world production troubleshooting scenario where DevOps engineers must debug build failures and restore deployment pipelines quickly.

The objective was to:

* Investigate Docker image build failure
* Analyze Dockerfile errors
* Fix incorrect file references
* Preserve existing configuration and application files
* Successfully build the Docker image

# Root Cause Analysis

The Dockerfile referenced files that did not exist in the expected locations.

Project Structure:

```text
/opt/docker
│
├── Dockerfile
├── certs
│   ├── server.crt
│   └── server.key
│
└── html
    └── index.html
```

Dockerfile Expected:

```text
server.crt
server.key
index.html
```

Dockerfile Reality:

```text
certs/server.crt
certs/server.key
html/index.html
```

Path mismatch caused the build failure.

# Problematic Section

Wrong:

```dockerfile
RUN cp certs/server.crt /usr/local/apache2/conf/server.crt

RUN cp certs/server.key /usr/local/apache2/conf/server.key

COPY ./index.html /usr/local/apache2/htdocs/
```

---

# Why It Failed

Docker build stages run inside temporary containers.

Files on host are unavailable unless explicitly copied.

Wrong approach:

```dockerfile
RUN cp certs/server.crt ...
```

Correct approach:

```dockerfile
COPY certs/server.crt ...
```

---

# Corrected Dockerfile

```dockerfile
FROM httpd:2.4.43

RUN sed -i "s/Listen 80/Listen 8080/g" /usr/local/apache2/conf/httpd.conf

RUN sed -i '/LoadModule\ ssl_module modules\/mod_ssl.so/s/^#//g' conf/httpd.conf

RUN sed -i '/LoadModule\ socache_shmcb_module modules\/mod_socache_shmcb.so/s/^#//g' conf/httpd.conf

RUN sed -i '/Include\ conf\/extra\/httpd-ssl.conf/s/^#//g' conf/httpd.conf

COPY certs/server.crt /usr/local/apache2/conf/server.crt

COPY certs/server.key /usr/local/apache2/conf/server.key

COPY html/index.html /usr/local/apache2/htdocs/
```

# Understanding COPY

Syntax:

```

Example:

```

---

# COPY vs RUN cp

## COPY

```dockerfile
COPY file destination
```

Uses files from build context.

---

## RUN cp

```dockerfile
RUN cp file destination
```

Works only inside container filesystem.

Cannot access host files.

# Common Mistakes

## Mistake 1 – Using RUN cp for Host Files

Wrong:

```dockerfile
RUN cp certs/server.crt ...
```

Correct:

```dockerfile
COPY certs/server.crt ...
```

---

## Mistake 2 – Incorrect Relative Paths

Wrong:

```dockerfile
COPY index.html ...
```

Actual file:

```text
html/index.html
```

Correct:

```dockerfile
COPY html/index.html ...
```

---

## Mistake 3 – Editing Base Image

Task specifically prohibited modifying:

```dockerfile
FROM httpd:2.4.43
```

---

## Mistake 4 – Building Outside Context

Wrong:

```bash
docker build /tmp
```

Correct:

```bash
cd /opt/docker
docker build .
```

# Interview Questions

## 1. What is Docker Build Context?

The set of files available to Docker during image build.

Usually:

```bash
docker build .
```

uses the current directory as build context.

---

## 2. Difference Between COPY and RUN cp?

| COPY                     | RUN cp                        |
| ------------------------ | ----------------------------- |
| Uses host files          | Uses container files          |
| Build-time instruction   | Runtime command               |
| Works with build context | Cannot access host filesystem |

---

## 3. Why Did the Build Fail?

Because Dockerfile referenced files using incorrect paths and attempted to access host files using RUN cp.
