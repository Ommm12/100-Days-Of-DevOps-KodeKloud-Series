# Day 87 – Install Package on App Servers Using Ansible

---

# Task Overview

The Nautilus Application Development team needed a common package installed across all application servers. Instead of manually logging into each server and installing the package, the DevOps team automated the entire process using Ansible.

The objective was to:

* Create an Ansible inventory containing all application servers
* Create an Ansible playbook
* Install the `chrony` package on all servers
* Use the Ansible Yum module
* Execute package installation from a central controller

# What is Chrony?

Chrony is a Network Time Protocol (NTP) implementation used for:

* Time synchronization
* Clock management
* Accurate system time

Example:

```text
NTP Server
      │
      ▼
Chrony Service
      │
      ▼
System Clock
```

---

# Why Accurate Time Matters

DevOps systems depend on synchronized clocks for:

* Logs
* Monitoring
* Security
* Kubernetes
* Databases
* CI/CD Pipelines

Without synchronized time:

```text
Server A → 10:00
Server B → 10:05
Server C → 09:58
```

Debugging becomes difficult.

The Yum Module manages packages on:

Equivalent Linux command:

---

# Step 4 – Create Playbook

```bash
vi playbook.yml
```

---

# Step 5 – Add Playbook Content

```yaml
---
- name: Install Chrony Package
  hosts: all
  become: yes

  tasks:

    - name: Install chrony
      yum:
        name: chrony
        state: present
```

Save file.

# Common Mistakes

## Mistake 1 – Missing Become

Wrong:

```yaml
hosts: all
```

Correct:

```yaml
hosts: all
become: yes
```

Package installation requires elevated privileges.

---

## Mistake 2 – Wrong Package Name

Wrong:

```yaml
name: chrono
```

Correct:

```yaml
name: chrony
```

---

## Mistake 3 – Using Latest Instead of Present

Wrong:

```yaml
state: latest
```

Task only requires installation.

Correct:

```yaml
state: present
```

---

## Mistake 4 – Inventory Missing Hosts

Verify:

```ini
stapp01
stapp02
stapp03
```

All servers must exist in inventory.
