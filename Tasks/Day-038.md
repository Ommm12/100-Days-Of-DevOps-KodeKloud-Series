# Day 38 – Pull and Re-Tag a Docker Image

---

# Task Overview

The Nautilus project developers planned to test application features in a containerized environment. To prepare the testing environment, the DevOps team needed to download a Docker image and create a new custom tag for it.

The objective was to:

- Pull the Docker image:

```bash
busybox:musl
```

- Create a new tag:

```bash
busybox:blog
```

- Verify both image tags exist locally

```text
Docker Hub

      ▼
```

```text
       ▼
```

# What is BusyBox?

BusyBox is a lightweight Linux image commonly used for:

- Testing
- Troubleshooting
- Containers
- Embedded systems

Size:

```text
Very Small
Very Fast
```

Perfect for container testing.

# What is a Docker Tag?

A tag is a human-readable label attached to a Docker image.

Example:

```bash
nginx:latest
ubuntu:22.04
busybox:musl
```

Format:

```text
image:tag
```




| Part | Meaning |
|----------|----------|

| busybox:blog | New tag |

Both tags should appear.

# Important Concept – Image Tagging

Tags help identify:

- Versions
- Environments
- Releases
- Custom builds

Examples:

```bash
myapp:v1
myapp:v2
myapp:prod
myapp:test
```

---

# Why Create Multiple Tags?

One image can have many tags.

Example:

```bash
myapp:latest
myapp:production
myapp:stable
```

All may point to the same image.

---

# Common Mistakes

## Mistake 1 – Wrong Tag Syntax

Wrong:

```bash
docker tag busybox blog
```

Correct:

```bash
docker tag busybox:musl busybox:blog
```

---

## Mistake 2 – Forgetting Pull

Wrong:

```bash
docker tag busybox:musl busybox:blog
```

before image exists.

Always:

```bash
docker pull
```

first.

---

## Mistake 3 – Typing Wrong Tag Name

Task Required:

```bash
busybox:blog
```

Not:

```bash
busybox:blogs
busybox:latest
```

---

## Mistake 4 – Confusing Tag with New Image

Tagging does NOT create a new image.

Both tags point to:

```text
Same IMAGE ID
```

# Interview Questions

## 1. What does `docker pull` do?

Downloads an image from a container registry such as Docker Hub.

---

## 2. What is a Docker Tag?

A label used to identify a specific version or variant of a Docker image.

---

## 3. Does `docker tag` create a new image?

No.

It creates a new reference to an existing image.

---

## 4. How can you verify two tags point to the same image?

Using:

```bash
docker images
```

and comparing:

```bash
IMAGE ID
```

---

## 5. Why do DevOps teams use image tags?

For:

- version control
- deployments
- rollbacks
- environment management
