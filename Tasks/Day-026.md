# Day 26 – Configure Git Remotes and Push Changes to a New Remote

---

# Task Overview

The xFusionCorp development team was working on the repository:

```bash
/usr/src/kodekloudrepos/games
```

Recently, the DevOps team added a new remote repository and required updates to the local repository configuration.

The objective was to:

- Add a new Git remote named `dev_games`
- Point it to the repository:

```bash
/opt/xfusioncorp_games.git
```

- Copy a file into the repository
- Commit changes to the master branch
- Push the master branch to the newly added remote

# Step-by-Step Implementation

## Step 1 – Connect to Storage Server

```bash
ssh natasha@ststor01
```

### Explanation

The `ssh` command establishes a secure connection to the Storage Server where the repository is located.

---

# Step 2 – Navigate to Repository

```bash
cd /usr/src/kodekloudrepos/games
```

### Explanation

Moves into the repository where Git operations will be performed.

---

# Step 3 – Check Existing Remotes

```bash
git remote -v
```

### Example Output

```bash
origin  /opt/games.git (fetch)
origin  /opt/games.git (push)
```

### Explanation

Displays currently configured remote repositories.

---

# Step 4 – Add New Remote Repository

```bash
git remote add dev_games /opt/xfusioncorp_games.git
```

### Explanation

Creates a new remote named:

```bash
dev_games
```

pointing to:

```bash
/opt/xfusioncorp_games.git
```

### Command Breakdown

| Part | Meaning |
|---------|---------|
| git remote | Manage remote repositories |
| add | Create new remote |
| dev_games | Remote name |
| /opt/xfusioncorp_games.git | Remote repository path |

---

# Step 5 – Verify New Remote

```bash
git remote -v
```

### Expected Output

```bash
origin      /opt/games.git
dev_games   /opt/xfusioncorp_games.git
```

### Explanation

Confirms the new remote has been added successfully.

---

# Step 6 – Copy Required File


# Step 7 – Verify File

# Step 8 – Add File to Git Staging Area


### Explanation

Stages the file so it can be included in the next commit.

---

# Step 9 – Commit Changes


### Explanation

Creates a commit containing the staged changes.

# Step 10 – Push to New Remote


### Explanation

Uploads the master branch to the newly configured remote repository.

| Part | Meaning |
|---------|---------|
| git push | Upload changes |

# Important Concept – Git Remotes

## What is a Remote Repository?

A remote repository is a Git repository stored outside the local machine.

It allows:

- Team collaboration
- Code sharing
- Backup and recovery
- CI/CD integration

---

# Multiple Remotes in Git

Git supports multiple remotes.

Example:

```text
origin      → Main Repository
dev_games   → Development Repository
backup      → Backup Repository
```

---

# Why Multiple Remotes Are Used

Organizations often use:

- Production repository
- Development repository
- Backup repository
- Migration repository

This allows flexibility in deployment and collaboration workflows.

---

# Real DevOps Insight

A common production setup:

```text
Developer
    │
    ▼
Git Repository
    │
 ┌──┴───────┐
 ▼          ▼
Origin    Backup Remote
```

Multiple remotes improve:

- Availability
- Disaster recovery
- Deployment flexibility
