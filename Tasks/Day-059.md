# Day 59 – Troubleshoot Deployment Issues in Kubernetes

---

# Task Overview

The Nautilus DevOps team discovered that a Redis application running on Kubernetes had suddenly stopped working. A recent configuration change introduced multiple mistakes in the Deployment manifest, causing the Pods to remain unavailable.

The task was not to create a new Deployment but to **troubleshoot an existing production issue**, identify the root causes, fix the Deployment, and restore the application.

This was one of the most realistic DevOps troubleshooting tasks in the Kubernetes journey.

The objective was to:

* Investigate Deployment failures
* Identify configuration mistakes
* Correct image and ConfigMap issues
* Restart Deployment
* Verify Pods return to Running state

# Common Mistakes

## Mistake 1 – Incorrect Image Name

Wrong:

```yaml
redis:alpin
```

Correct:

```yaml
redis:alpine
```

---

## Mistake 2 – Typo in ConfigMap Name

Wrong:

```yaml
redis-cofig
```

Correct:

```yaml
redis-config
```

---

## Mistake 3 – Restarting Before Fixing

Wrong:

```bash
kubectl rollout restart deployment redis-deployment
```

before correcting YAML.

Always fix configuration first.

---

## Mistake 4 – Ignoring Events

Many engineers check only logs.

Always check:

```bash
kubectl describe pod
```

and

```bash
kubectl get events
```
