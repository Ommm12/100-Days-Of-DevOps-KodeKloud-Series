# Day 99 – Attach IAM Policy for DynamoDB Access Using Terraform

---

# Task Overview

As the Nautilus DevOps team's cloud infrastructure grew, securing access to data became a top priority. The team needed a DynamoDB table along with a dedicated IAM Role and IAM Policy that followed the Principle of Least Privilege.

Instead of granting full access to DynamoDB, the requirement was to allow only read operations on a specific table using a custom IAM policy.

The objective was to:

* Create a DynamoDB table
* Create an IAM role
* Create a read-only IAM policy
* Attach the policy to the role
* Use Terraform variables and outputs
* Restrict permissions to only one DynamoDB table

# What is an IAM Role?

An IAM Role is a set of permissions that AWS services can assume.

Example:

```text id="dhml6s"
EC2
 │
 ▼
IAM Role
 │
 ▼
DynamoDB Access
```

Unlike IAM Users:

```text id="nwlqzi"
IAM User
     │
     ▼
Human Access
```

Roles are designed for services and applications.

---

# What is an IAM Policy?

An IAM Policy defines:

```text id="nq0xmk"
Who

Can Do What

On Which Resource
```

Example:

```json id="m6w3gm"
{
  "Effect": "Allow",
  "Action": "dynamodb:GetItem"
}
```

# Step 3 – Create main.tf

```bash id="v1x6bx"
vi main.tf
```

Add:

```hcl id="7hhl76"
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
      version = "5.91.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_dynamodb_table" "table" {

  name = var.KKE_TABLE_NAME

  billing_mode = "PAY_PER_REQUEST"

  hash_key = "id"

  attribute {
    name = "id"
    type = "S"
  }
}

resource "aws_iam_role" "role" {

  name = var.KKE_ROLE_NAME

  assume_role_policy = jsonencode({
    Version = "2012-10-17"

    Statement = [
      {
        Effect = "Allow"

        Principal = {
          Service = "ec2.amazonaws.com"
        }

        Action = "sts:AssumeRole"
      }
    ]
  })
}

resource "aws_iam_policy" "policy" {

  name = var.KKE_POLICY_NAME

  policy = jsonencode({

    Version = "2012-10-17"

    Statement = [
      {
        Effect = "Allow"

        Action = [
          "dynamodb:GetItem",
          "dynamodb:Scan",
          "dynamodb:Query"
        ]

        Resource = aws_dynamodb_table.table.arn
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "attach" {

  role       = aws_iam_role.role.name

  policy_arn = aws_iam_policy.policy.arn
}
```

Save file.

# Interview Questions

## 1. What is DynamoDB?

AWS's fully managed NoSQL database service.

---

## 2. Difference between IAM Role and IAM User?

| IAM User              | IAM Role              |
| --------------------- | --------------------- |
| Human Access          | Service Access        |
| Permanent Credentials | Temporary Credentials |

---

## 3. What is Least Privilege?

Granting only the minimum permissions required.

---

## 4. Why attach a policy to a role?

Policies define permissions, while roles use those permissions.

---

## 5. Why restrict the policy to a specific table ARN?

To prevent access to other DynamoDB resources and improve security.
