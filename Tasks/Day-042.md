# Day 42 – Create a Custom Docker Bridge Network

---

# Task Overview

The Nautilus DevOps team needed a dedicated Docker network for future container deployments. The requirement was to create a custom bridge network with a specific subnet and IP range configuration.

Custom Docker networks provide better isolation, container communication, and network management compared to the default Docker bridge network.

The objective was to:

* Create a Docker network named `news`
* Use the `bridge` network driver
* Configure subnet `172.168.0.0/24`
* Configure IP range `172.168.0.0/24`
* Verify network creation

# Understanding the Problem

Default Docker Networking:

```text
Container A
      │
      ▼
Default Bridge Network
      │
      ▼
Container B
```

Required Setup:

```text
Container A
      │
      ▼
news Network
      │
      ▼
Container B
```

This creates a dedicated network for application containers.

---

# What is a Docker Network?

A Docker network enables communication between:

* Containers
* Containers and Host
* Containers and External Networks

Docker automatically assigns:

* IP Addresses
* DNS Resolution
* Network Isolation

---

# Why Use Custom Networks?

Benefits:

* Better isolation
* Improved security
* Easier service discovery
* Predictable IP allocation
* Application segmentation

---

# Docker Network Drivers

| Driver  | Purpose                            |
| ------- | ---------------------------------- |
| bridge  | Single host container networking   |
| host    | Uses host network directly         |
| overlay | Multi-host networking              |
| macvlan | Assign MAC addresses to containers |
| none    | No networking                      |

For this task:

```text
bridge
```

was required.

# Step-by-Step Implementation

## Step 1 – Connect to App Server

```bash
ssh tony@stapp01
```

### Explanation

Connects to the application server where Docker is installed.

---

# Step 2 – Verify Docker Service

```bash
sudo systemctl status docker
```

### Explanation

Ensures Docker daemon is running before creating networks.

---

# Step 3 – List Existing Networks

```bash
docker network ls
```

### Example Output

```text
NETWORK ID     NAME      DRIVER
xxxxxxx        bridge    bridge
xxxxxxx        host      host
xxxxxxx        none      null
```

### Explanation

Displays all available Docker networks.

---

# Step 4 – Create Custom Network

```bash
sudo docker network create \
--driver bridge \
--subnet 172.168.0.0/24 \
--ip-range 172.168.0.0/24 \
news
```

### Explanation

Creates a custom bridge network named:

```text
news
```

---

# Command Breakdown

| Option                | Meaning                |
| --------------------- | ---------------------- |
| docker network create | Create new network     |
| --driver bridge       | Use bridge driver      |
| --subnet              | Define subnet          |
| --ip-range            | Define usable IP range |
| news                  | Network name           |

# Common Mistakes

## Mistake 1 – Wrong Driver

Wrong:

```bash
docker network create --driver host news
```

Correct:

```bash
docker network create --driver bridge news
```

---

## Mistake 2 – Incorrect Subnet

Wrong:

```bash
--subnet 172.168.0.0/16
```

Correct:

```bash
--subnet 172.168.0.0/24
```

---

## Mistake 3 – Docker Service Not Running

Error:

```text
Cannot connect to Docker daemon
```

Fix:

```bash
sudo systemctl start docker
```

---

## Mistake 4 – Network Already Exists

Error:

```text
network with name news already exists
```

Verify:

```bash
docker network ls
```
