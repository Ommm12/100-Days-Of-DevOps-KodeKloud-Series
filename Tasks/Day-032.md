# Task Overview

The Nautilus application development team was working on the repository:

```bash
/opt/blog.git
```

which was cloned under:

```bash
/usr/src/kodekloudrepos/blog
```

One of the developers was actively working on the `feature` branch while new commits had already been added to the `master` branch.

The developer wanted to:

- Update the feature branch with the latest changes from master
- Avoid creating a merge commit
- Preserve all work done in the feature branch
- Maintain a clean and linear Git history

The solution was to perform a:

```bash
git rebase
```

# Understanding the Problem

Current Repository Structure:

```text

```

```text

```

```text

```

```text
A --- B --- C --- D --- E
```

without:

```text
Merge Commit
```

---

# What is Git Rebase?

Git Rebase moves a branch to a new base commit.

Instead of creating a merge commit:

```text
master
    │
    ▼
feature
```

Git takes feature commits and replays them on top of master.

---

# Merge vs Rebase

## Merge

```text
A --- B --- C
      \     \
       D --- E --- M
```

Creates:

```text
Merge Commit (M)
```

---

## Rebase

```text
A --- B --- C --- D --- E
```

No merge commit.

Cleaner history.

# Common Mistakes

## Mistake 1 – Rebasing Wrong Branch

Wrong:

```bash
git checkout master
git rebase feature
```

Always:

```bash
git checkout feature
git rebase master
```

---

## Mistake 2 – Forgetting Force Push

Wrong:

```bash
git push origin feature
```

Results:

```text
Rejected
```

Correct:

```bash
git push origin feature --force
```

---

## Mistake 3 – Using Merge Instead

Wrong:

```bash
git merge master
```

Task specifically required:

```text
No Merge Commit
```

---

## Mistake 4 – Ignoring Rebase Conflicts

If conflicts occur:

```bash
git status
```

Resolve files then:

```bash
git add .
git rebase --continue
```

# Interview Questions

## 1. What is Git Rebase?

Git Rebase moves a branch to a new base commit and replays its commits on top of another branch.

---

## 2. Why use Rebase instead of Merge?

Rebase creates a cleaner and linear commit history without merge commits.

---

## 3. Does Rebase rewrite history?

Yes.

Rebase creates new commit hashes.

---

## 4. Why is Force Push needed after Rebase?

Because commit history changes and local history no longer matches remote history.

---

## 5. What happens if conflicts occur during Rebase?

Resolve conflicts manually and continue using:

```bash
git rebase --continue
```
