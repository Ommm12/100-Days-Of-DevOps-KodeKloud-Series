# Task Overview

As the Nautilus DevOps team continued building AWS infrastructure, the next focus area was **Identity and Access Management (IAM)**.

In AWS, security is not just about firewalls and networking. It is equally important to control **who can access what resources** and **what actions they can perform**.

For this task, Terraform was used to create a custom IAM policy that provides **read-only access to Amazon EC2 resources**, allowing users to view instances, AMIs, and snapshots without making any modifications.

The objective was to:

* Create an IAM Policy using Terraform
* Name the policy `iampolicy_javed`
* Allow read-only access to EC2 resources
* Deploy the policy in AWS using Infrastructure as Code
* Understand IAM security best practices

# What is an IAM Policy?

An IAM Policy is a JSON document that defines:

```text
Who
 │
 ▼
Can Do What
 │
 ▼
On Which Resources
```

Example:

```json
{
  "Effect": "Allow",
  "Action": "ec2:DescribeInstances",
  "Resource": "*"
}
```

---

# What Does Read-Only Mean?

Read-only access allows:

```text
View Resources
List Resources
Describe Resources
```

Examples:

```text
DescribeInstances

DescribeImages

DescribeSnapshots
```

Principle:


Instead of:


Use:

```text
Read Only Access
```

This is a core DevOps and Cloud Security practice.

# Step 3 – Add Terraform Configuration

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_iam_policy" "iampolicy_javed" {

  name = "iampolicy_javed"

  description = "Read only access to EC2 resources"

  policy = jsonencode({
    Version = "2012-10-17"

    Statement = [
      {
        Effect = "Allow"

        Action = [
          "ec2:DescribeInstances",
          "ec2:DescribeImages",
          "ec2:DescribeSnapshots"
        ]

        Resource = "*"
      }
    ]
  })
}
```

Save and exit.

# Common Mistakes

## Mistake 1 – Using Full EC2 Access

Wrong:

```hcl
Action = ["ec2:*"]
```

Provides excessive permissions.

---

## Mistake 2 – Missing Describe Permissions

Wrong:

```hcl
Action = ["ec2:StartInstances"]
```

Task specifically requires viewing resources.

---

## Mistake 3 – Wrong Policy Name

Wrong:

```hcl
name = "readonly"
```

Correct:

```hcl
name = "iampolicy_javed"
```

---

## Mistake 4 – Invalid JSON

Wrong:

```hcl
policy = "{invalid}"
```

Use:

```hcl
jsonencode()
```

to avoid syntax issues.
