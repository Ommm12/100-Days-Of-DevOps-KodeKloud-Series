#  Day 07 – Password-less SSH Authentication Setup

##  Task Overview
The system administration team at **xFusionCorp Industries** had automated scripts running from the Jump Host to perform operational tasks across all application servers in the Stratos Datacenter.

To ensure seamless automation without manual password prompts, the infrastructure required **password-less SSH authentication** between the Jump Host and all application servers.

###  Objective

Configure password-less SSH authentication from user:

```bash
thor
```

on the **Jump Host** to all application servers using their respective sudo users.

---

#  Why This Task Matters

In real-world DevOps and production environments, automation tools and scripts rely heavily on password-less authentication.

This is commonly used in:
- Ansible automation
- CI/CD pipelines
- Deployment scripts
- Monitoring systems
- Backup automation

Without SSH key-based authentication:
- Scripts stop for password prompts
- Automation fails
- Infrastructure operations become inefficient

---

#  Step-by-Step Implementation

---

# 🔹 Step 1: Generate SSH Key Pair on Jump Host

Login to Jump Host and run:

```bash
ssh-keygen -t rsa
```

###  Explanation
This command generates:
- Private Key → `~/.ssh/id_rsa`
- Public Key → `~/.ssh/id_rsa.pub`

During setup:

```bash
Enter file in which to save the key:
```

Press:

```bash
Enter
```

to use the default location.

When asked for passphrase:

```bash
Enter passphrase:
```

Press:

```bash
Enter
```

twice to leave it empty.

---

# 🔹 Step 2: Verify SSH Keys

```bash
ls -l ~/.ssh
```

###  Explanation
You should see:

```bash
id_rsa
id_rsa.pub
```

- `id_rsa` → Private key  
- `id_rsa.pub` → Public key  

---

# 🔹 Step 3: Copy Public Key to App Server 1

```bash
ssh-copy-id tony@stapp01.stratos.xfusioncorp.com
```

###  Explanation
This copies the public SSH key to:

```bash
~/.ssh/authorized_keys
```

on the remote server.

Enter password once when prompted.

---

# 🔹 Step 4: Copy Public Key to App Server 2

```bash
ssh-copy-id steve@stapp02.stratos.xfusioncorp.com
```

Enter password once.

---

# 🔹 Step 5: Copy Public Key to App Server 3

```bash
ssh-copy-id banner@stapp03.stratos.xfusioncorp.com
```

Enter password once.

---

# 🔹 Step 6: Test Password-less SSH Login

## App Server 1
```bash
ssh tony@stapp01.stratos.xfusioncorp.com
```

## App Server 2
```bash
ssh steve@stapp02.stratos.xfusioncorp.com
```

## App Server 3
```bash
ssh banner@stapp03.stratos.xfusioncorp.com
```

###  Explanation
If configured correctly:
- SSH login should happen directly
- No password should be requested

#  Security Best Practices

- Protect private keys carefully
- Never share `id_rsa`
- Use SSH keys instead of passwords whenever possible
- Use passphrases in production environments
- Rotate SSH keys periodically
