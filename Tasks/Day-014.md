# Day 14 – Apache Service Recovery on Multiple Servers

## Task Overview
The monitoring platform detected Apache service unavailability on one of the application servers.

The requirement was to:
- Identify the faulty host
- Restore Apache service
- Ensure Apache runs on port 3002 across all app servers

---

# Objective

- Identify failed Apache instance
- Configure Apache on port 3002
- Ensure service availability on all app servers

---

# Step-by-Step Implementation

## Step 1: Connect to Each App Server

```bash
ssh user@server
```

---

## Step 2: Check Apache Status

```bash
sudo systemctl status httpd
```

---

## Step 3: Configure Apache Port

```bash
sudo vi /etc/httpd/conf/httpd.conf
```

Set:

```bash
Listen 3002
```

---

## Step 4: Stop Conflicting Services

```bash
sudo systemctl stop sendmail
sudo systemctl disable sendmail
```

---

## Step 5: Restart Apache

```bash
sudo systemctl restart httpd
sudo systemctl enable httpd
```

---

## Step 6: Verify Port

```bash
sudo ss -tulnp | grep 3002
```

---

# Key Learnings

- Multi-server troubleshooting
- Apache service recovery
- Port conflict handling
- Production monitoring response
- Infrastructure consistency

---

# Final Outcome

- Apache restored across all servers
- Port standardized to 3002
- Service availability verified
